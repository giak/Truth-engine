## Structure

- `00_README` : guide, lineage, limites.
- `01_ARTICLE_VERSIONS` : versions successives et annexe.
- `02_INVESTIGATIONS` : enquêtes ayant alimenté l'article.
- `03_AUDITS_QA` : audits multirôles, double-checks, P0/P1.
- `04_TRACEABILITY` : dashboard, SQLite, manifeste, snapshot de régression.
- `05_CONVERSATION` : événements de conversation disponibles localement.
- `06_METHOD_PROMPTS` : prompts/méthodes conservés.
- `07_FIGURES` : schémas finaux V3.1 en SVG et PNG.
- `08_VISUAL_ITERATIONS` : images d'illustration générées/essayées.
- `09_REFERENCE_STYLE_FACTCHECK` : SVG/PNG de référence ayant inspiré les figures.
- `10_HISTORY_BUNDLES` : bundles successifs de passation.
- `11_SOURCE_INPUTS` : bundle source initial disponible localement.

## Vérification

`MANIFEST_SHA256.txt` contient le SHA-256 de chaque fichier.
`INVENTORY.csv` et `INVENTORY.json` documentent provenance, rôle et statut canonique.

## Limites

Lire impérativement `KNOWN_GAPS.md`.
En particulier :
- pas de transcript brut intégral du chat ;
- pas de snapshot immuable pour la majorité des sources web ;
- un SQLite racine régressé a été détecté et conservé comme trace, mais **n'est pas canonique**.
