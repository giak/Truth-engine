## 4. Contenu d'une passe KERNEL

Chaque sous-dossier contient les fichiers suivants (préfixe `YYYY-MM-DD_HH-MM_<slug>_` sauf exception) :

| Fichier | Rôle |
|---|---|
| `*_INVESTIGATION.md` | **Livrable lisible** (l'enquête rédigée, registres V1) |
| `*_NARRATIVE.tmp.md` | Brouillon de rédaction |
| `*_RUN_STATE.json` | État machine du run (QRY/SRC/FCT/objets/compteurs) |
| `*_CERTIFICATION.json` | Verdict de certification (gate delivery) |
| `*_MNEMO_SNAPSHOT.json` | Snapshot de persistance MnemoLite |
| `*_INPUT.txt` | Sujet/demande de la passe |

> **⚠️** : suites strictement internes au moteur à ignorer si présentes : `_repair_backups/`, `_replay_backups/`.

## 5. Artefacts intermédiaires

Le sous-dossier **`_artefacts_tmp/`** regroupe les **fichiers de travail jetables** produits pendant les passes (payloads temporaires `tmp_*.json`, brouillons `draft_narrative_*.md`, scripts de persistance `persist_*.py`). Ils ont été **consommés** dans les RUN_STATE/délivrables des passes et n'ont plus de valeur probatoire — conservés ici par précaution (trace), pas à la racine du projet.
